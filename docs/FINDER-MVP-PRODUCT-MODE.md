# Public product and evidence boundaries

The deployment uses `GRIDPULSE_PRODUCT_MODE` (finder/connect/full) and independently
selected solutions. Unknown product modes fail closed to finder. The executable route
policy in src/config/product-mode.ts and solution ownership in src/config/solutions.ts
are authoritative; this document is not a second route allowlist.

## Current public experience

Site Selection exposes Power Finder and the device-local Sites portfolio, workspaces and
capacity dossiers. Public sector and source pages remain available. Facility Operations
is controlled independently by the selected solutions. Finder mode does not mean that
all Operations pages are disabled. Private assessment/operator routes remain restricted.
Authentication capability is currently disabled in all three modes; changing a mode
alone does not establish authenticated workspace access.

The public Finder reads bounded public RPCs and admitted static fallback assets. Geographic
bounds do not establish accepted coverage: active governed releases determine coverage.
A failed origin may expose only the intersecting Brandenburg fallback, clearly labelled
with its source date and limited scope. Other regions remain unavailable. Missing capacity
is never zero and a query timestamp is never a source publication date.

## Capacity and calculation policy

Finder mode rejects capacity URL state and does not load a synthetic capacity overlay.
Synthetic electrical demonstrations belong to the separate network-study experience.
A mapped private or customer substation remains an investigation lead with explicit
third-party-access limitations. Operator tags do not establish network responsibility.
Public rankings measure investigation context, not MW, suitability or connection probability.

The canonical analytical service owns optimisation and physical replay. Public synthetic
planning does not accept separately qualified German market assumptions. Operator studies,
contractual permissions and measured delivery remain separate evidence classes. All current
Operations workspace contracts retain automaticDispatchAuthorized: false.

## Local storage

Sites and evidence stored in the anonymous workspace are device-local. Users must export
backups for portability; browser storage is not a cloud collaboration or disaster-recovery
service. New candidate snapshots preserve captured evidence dates, suitability limitations,
retrieval caps and a hash of the retrieved input. A hash detects changed evidence; it does
not recreate an unavailable upstream dataset. Immutable source retention remains a separate
operator-pilot requirement.

## Changes requiring separate qualification

Enabling private workspaces requires authentication, owner isolation and storage-policy
validation against an authorised non-production environment. Enabling live operations
requires measured telemetry, calibration, local safety controls, device authority and
independent approval. Mode switches cannot create any of those qualifications.

No schema/data/billing change, deployment, source redistribution, paid integration or
parked PR #37 work is implied by this implementation.
